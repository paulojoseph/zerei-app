# Zerei.app

**Your log of every game you've ever beaten.** A personal catalog to record everything you finished in your life, from the Master System you rented at the corner video store to the PS5, with the year you beat it, the score you'd give it and that one note that only makes sense to you.

"Zerei" is Brazilian gamer slang for "I beat it". The app was born for the Brazilian retro gaming community (Tec Toy consoles, arcades, rental stores), but it works for anyone.

It's not a social network, there's no login and nothing leaves your browser. It's the shelf of finished games you never had.

`Next.js 16` · `React 19` · `TypeScript 5.9 (strict)` · `Tailwind CSS v4` · `Zustand 5` · `PWA`

---

## Getting started

Requires **Node.js 20.9 or later**.

```bash
npm install
npm run dev
```

Open **http://localhost:3000**.

No database, account, API key or internet connection needed: the app ships with its game database built in.

---

## Where your data lives

The catalog is static: the curated list in `data/seed-games.json` and the full per-console catalog in `public/catalog/` (generated by `npm run catalog`, see below). All your progress (status, year you beat it, score and notes) is saved in the **browser's LocalStorage**, under the `zerei-app-storage` key.

This means that:

- no data is ever sent to any server;
- records are per browser and per device (what you marked on your phone won't show up on your desktop);
- clearing site data, using a private tab or switching browsers **wipes everything**.

That's why the backup below is not just decoration.

---

## Backup

The backup menu in the header lets you:

- **Export JSON**: the full file (progress plus games you added by hand). This is the file that restores everything later.
- **Export CSV**: the same information as a spreadsheet, to open in Excel or Google Sheets. Good for browsing and printing, not for restoring.
- **Import**: pick a JSON exported by the app itself, in one of two modes:
  - **Merge** (default): combines it with what you already have; when the same game conflicts, the most recent record wins;
  - **Replace**: discards what's in the browser and keeps only the file contents.

Tip: export a JSON every now and then and keep it next to your photos. It's a text file of a few KB.

## IGDB (optional)

Search works with nothing configured, looking through the local database. If you also want to find games that aren't in it, you can turn on **IGDB** (Twitch's games API):

1. Create an application at <https://dev.twitch.tv/console/apps> (the redirect URL can be `http://localhost:3000`).
2. Copy the example file:
   ```bash
   cp .env.example .env.local
   ```
3. Fill in both variables with your app's credentials:
   ```
   TWITCH_CLIENT_ID=your_client_id
   TWITCH_CLIENT_SECRET=your_client_secret
   ```
4. **Restart the dev server** (`Ctrl+C` and `npm run dev` again). Next.js only reads environment variables at startup.

Without credentials, the `/api/igdb/search` route just answers with local results and a notice. Nothing breaks.

## Features

- **Full per-console catalog**: from the Atari 2600 to the PS5 and Switch 2, tens of thousands of games, each with a cover.
- **Filter by maker and console**: Nintendo, Sony, Sega, Microsoft and more. One click on a maker shows all its consoles, another picks the console. Direct link: `/?console=snes` (ids in `data/consoles.json`).
- **Forgiving search**: ignores accents and understands nicknames, so `megadrive`, `genesis`, `snes`, `arcade`, `nintendinho` and `psx` find what you expect.
- **Status filters**: All, Beaten, Playing, Backlog and Not played.
- **"Rental Store & Brazil Classics" preset**: one click and you're left with what ran on the Tec Toy Mega Drive, the corner arcade and the neighborhood rental store.
- **Card with a "Beat it!" toggle**: marking a game as beaten is a single tap, right on the grid, without opening anything.
- **Memories modal**: status, year you beat it, a 1 to 5 star score and a free notes field ("beat it at my cousin's house, Saturday at 3am").
- **Stats panel**: total beaten, breakdown by generation and platform, average score, games beaten per year and a timeline of your latest wins.
- **Sorting**: recently updated, title, release year (newest or oldest) and best score.
- **Full backup**: JSON and CSV export, import with merge or replace.
- **Optional online search**: games found on IGDB join your catalog and travel along in the backup.
- **Installable PWA**: opens full screen with its own icon and keeps working offline.

## PWA: install to your home screen

The app has a manifest and icons, so you can install it like a real app:

- **Android (Chrome)**: menu `⋮` → **Install app** (or "Add to Home screen").
- **iPhone / iPad (Safari)**: **Share** button → **Add to Home Screen**.
- **Desktop (Chrome/Edge)**: install icon on the right side of the address bar.

Once installed, it opens without the browser bar, in dark mode, with two quick shortcuts: **Beaten** and **BR Nostalgia**.

The vector icons (`icon.svg` and `maskable.svg`) are the reference artwork; the PNGs required by Android and iOS come from `npm run icons`. If `public/icons/` only has the SVGs, run that command once.

## Where the catalog comes from

`npm run catalog` (`pipeline/build.mts`, [ADR 0004](docs/adr/0004-igdb-data-edition-model.md)) builds the catalog from [IGDB](https://www.igdb.com), which is free for non-commercial use with attribution. It needs `TWITCH_CLIENT_ID` and `TWITCH_CLIENT_SECRET` in `.env.local` (step by step at the top of `.env.example`).

- **Edition = game × console.** That's where the user marks "beaten". A Zerei console can group several IGDB platforms (NES = NES + Famicom).
- **Only actual games:** main game, remake, remaster, port, expanded and standalone. DLC, bundles, mods and episodes are left out.
- **A re-release is not an edition:** a game much older than the console (Virtual Console, PS one Classics, Arcade Archives) doesn't go into that console's list.
- **Popularity** (IGDB visits plus ratings) puts the classic ahead of the obscure. On PC only rated games get in (there are 180k in total).
- **Stable IDs** ([ADR 0002](docs/adr/0002-stable-ids.md)): an edition that matches a game from the previous catalog inherits its ID; regional duplicates ("Rockman 5" = "Mega Man 5") become aliases and progress migrates; anything IGDB doesn't have keeps its old source.
- **Output:** `public/catalog/<console>.json` (lean list), `top.json` (the most popular, for the first screen), `meta.json` (genre names) and, outside git, `.cache/pipeline/details/` (summary, companies, similar games, external IDs, the base for the next phases).

IGDB responses are cached in `.cache/igdb/`, so running it again takes seconds. `--only=nes,snes` builds just a few consoles; `--fresh` ignores the cache; `--allow-removals` deliberately accepts that a published ID disappears.

The app loads on demand: the first screen only fetches `top.json` (~84KB); each console arrives when it's picked or when the user has games marked on it.

## Adding more games

The database lives in **`data/seed-games.json`**: an array of objects, one per game. Add yours at the end of the file and reload the page.

```json
{
  "id": "sonic-2-md",
  "title": "Sonic the Hedgehog 2",
  "platform": "Mega Drive",
  "category": "16-bit",
  "releaseYear": 1992,
  "coverUrl": "",
  "summary": "Sonic and Tails team up against Dr. Robotnik's Death Egg.",
  "isBrazilClassic": true,
  "genres": ["Platformer", "Action"]
}
```

| Field | Required | Notes |
| --- | --- | --- |
| `id` | yes | Unique across the whole file. Use something stable, like `title-platform`, because it's the key for your progress in LocalStorage. **Never change the `id` of a published game**, or whoever already beat it loses the record. |
| `title` | yes | The name people search for. |
| `platform` | yes | Preferably one of the canonical names already used in `lib/platforms.ts` (`Mega Drive`, `Master System`, `Super Nintendo`, `PlayStation 2`...), so the game inherits the badge abbreviation and the search nicknames. |
| `category` | yes | One of `"8-bit"`, `"16-bit"`, `"32/64-bit"`, `"128-bit"` or `"modern"`. Any other value makes the row get dropped silently. |
| `releaseYear` | yes | A number, no quotes. |
| `coverUrl` | yes | An https cover URL, or `""`. Empty is fine: the app draws its own cover with the title and the generation color. |
| `summary` | no | One or two sentences. |
| `isBrazilClassic` | no | `true` marks the game as a rental store, arcade or Tec Toy classic and includes it in the **BR Nostalgia** preset. |
| `genres` | no | Array of strings; goes into the search index. |

Two details that save time:

- If you point `coverUrl` to a new domain, add the host to `remotePatterns` in `next.config.ts`, because `next/image` blocks undeclared origins.
- Instead of hunting for covers by hand, add the Wikipedia title to `data/cover-sources.json` and run `npm run covers`.
